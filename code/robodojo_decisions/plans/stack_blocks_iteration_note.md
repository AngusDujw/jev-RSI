1. **把 stage 改为控制器维护的状态。** 每轮先向 `gpt-6-luna` 发“观察与验收”请求：输入同一时刻的三张 RGB、两臂 LINK6 位姿、当前阶段和上次实际动作；只返回目标的图像标记、当前阶段完成证据、异常及 `pass / fail / uncertain`。每项证据必须注明相机与可见现象；`uncertain` 保持当前阶段，不能默认退回 `observe_blocks`。

2. **拆开验收与动作问题。** 控制器处理验收结果、确定阶段后，再发“动作”请求：给定固定阶段、目标图像标记、活动臂及最新观测，只问该臂的 XYZ 方向、步长、夹爪。动作请求不允许修改 stage。`select_arm` 单独决定活动臂并锁定；另一臂由控制器强制保持位置和夹爪状态。

3. **用证据推进观察与接近阶段。** `observe_blocks → select_arm`：RGB 中已标出待抓块、堆叠位置及遮挡情况；`select_arm → approach`：选定臂及可见接近路线；`approach → align`：夹爪已进入目标附近，且 LINK6 确认实际执行了接近动作；`align → grasp`：至少两个有效视角支持夹爪与目标抓取位置对齐、没有明显碰撞风险。证据不足时保持、缩小动作或调整观察位置，不按调用次数推进。

4. **抓取必须经过验证性微抬。** `grasp` 内先闭爪，再执行小幅试抬；只有 RGB 显示同一目标随夹爪上移、相对夹爪位置保持，并结合 LINK6 确认手臂确实上移，才进入 `lift`。随后确认目标离开原支撑面才进入 `move_to_stack`；夹爪闭合或手臂移动本身都不能算抓取成功。

5. **放置与最终成功分别验收。** `move_to_stack → place`：持有目标到达堆叠位置上方且视觉对齐；`place → release`：缓慢下降后，多视角支持目标已落到预期支撑位置；`release → retreat`：开爪后目标仍留在支撑处；`retreat → verify`：夹爪已与目标分离并退出遮挡；`verify` 用连续新观测确认堆叠成立、目标未滑落，才宣布成功。不可见的支撑关系返回 `uncertain`。

6. **按失败原因恢复，保留目标与活动臂。** 对齐偏差回 `align`；试抬未带起目标则重新放稳、开爪并回 `align`；搬运中掉落则回 `observe_blocks` 重新定位；放置后偏移或倒塌则先观察再规划恢复。若 LINK6 未响应动作，停止运动并报告执行故障；若 LINK6 在动但图像中的任务误差没有改善，暂停并重新判断路线。恢复依据是观测变化，不能靠“再跑若干步”。

7. **阶段与动作必须原子绑定。** 每个动作携带 `observation_id、stage、active_arm、target_id`，执行前逐项核对；观测过期、阶段已变或手臂不匹配就丢弃。控制器按阶段限制动作：观察/选臂不运动，接近/对齐保持开爪，搬运保持闭爪，释放才允许开爪；试抬仅允许在 `grasp` 的验收子状态执行。每次只执行一个有界微动作，回读 RGB 与 LINK6 后再决策，并记录“阶段前后、实际动作、转移证据或保持原因”。
