# stack_blocks 实体控制的实现准备

这是 Agent 的实现草稿，不是 GPT 规划器输出，也不是动作批准。旧回合只提供方法和失败证据；任何执行必须重新取得当前三 RGB、公开相机参数和实测机器人状态。

## 已知阻塞

- 旧顶面轮廓拟合提供了带不确定度的高度假设，但没有实际抓取。整块轮廓中心不是跨视角物理对应点。
- 旧白块旁局部放大、侧上视角、Y 路径没有建立源块运动，不能原样重跑。
- 与 general_pickup 相同，阶段退出证据不能被误作获取证据的动作前提；近距控制不能每帧换一个材料目标。

## 下一版的分工

规划器只确认任务角色、阶段退出条件、需要观察的物体部件与图像处理方法。源块、邻近物体和接收块的像素区域是感知描述，不是机器人动作。规划器不输出目标位姿或方向命令。

算法从当前区域分割、公开 K/T 和实测机器人状态生成：顶面/桌面高度区间、源块几何假设、真实指面到持续材料参考的误差，以及邻近物体空间关系。顶面不是侧面接触证书；假设的形状、高度与遮挡必须分别报告。源块附近的空隙决定需要审查哪种夹持方向，不能仅据高位二维重叠判断碰撞。

推进器看到原始三 RGB、真实 XYZ/旋转效果、当前阶段与同一材料参考的误差，选择一个算法生成的完整短程序或 STOP。所有程序重新通过公开五步路径、原生首 IK 和实际跟踪检查；没有真物体位姿、接触或评估值输入。

## 收敛证据

先实现源块包夹、可见源物随动，再验证接收块顶面关系、下降、释放和退让后的新图。一次程序只推进当前阶段，但剩余原生预算要用于全部阶段。原生 success 与 complete 分开记录；完整成功之后才开展独立重复和任务扩展。

相关历史：EXP117–121 的旧视角失败、EXP208 的材料参考跳换、EXP209–211 的捕获阶段与原生终局证据。实现时必须重读当前任务经验，并把评估结果留在人类经验中。
