# Reviewed cross-task experience (2026-10-11)

- Observation contract: only public task language, current calibrated RGB cameras, and robot proprioception are available. Stereo box centres and RGB silhouettes are estimates; never treat a last-seen point, neutral orientation placeholder, or gripper command as true object pose, grasp, or success.
- Planner: declare visual identity cues and implemented detection/triangulation operators before motion. Give every object-dependent stage an explicit freshness requirement, a measurable end condition, and a bounded reobservation or recovery route. Reserve GPT replanning for semantic milestones or genuine failed evidence, because repeated visual localization has caused long delays and identity loss.
- Decision model: use current motor residual and deadband for signed axes. Inspect selected live images for visible contradiction, occlusion, wrong target, lost hold, and changed receiver. Request reobservation or replanning before acting on an uncertain relation; do not override an axis sign from image parallax alone.
- After apparent closure, verify object motion relative to the gripper during a short lift. After apparent placement, verify the released relation from fresh RGB. Keep native success strictly as an offline result.
- A prior failed episode is diagnostic evidence, never a demonstration to replay. Re-ground every historical lesson in the current images. Sources: `code/old/experience/`; server02 vision-method campaign records in `/data/ykj_robodojo/RoboLaya/runs/vision-method-20261011/`.
- A camera-search stage is for acquiring currently missing evidence: mark it `purpose=sense`, keep its arm target robot-state-only, and treat required stereo/identity as an end condition rather than an entry gate. The decision model should allow a bounded, safe viewpoint change even while the target is occluded. Stop only for a concrete visible contradiction or unsafe path. Localize the next source/receiver pair needed for physical work; avoid repeated all-object stereo searches that consume the native episode budget.
- If a manipulation stage can use refreshed `now.o` camera estimates and has explicit visual entry gates, plan it directly after the bounded sensing stage. RGB is refreshed at every decision, so an extra GPT handoff after each viewpoint move is unnecessary unless the new evidence changes the intended operation. For ordered multi-object tasks, acquire and act on the next target first, then handle the remaining targets.
- For repeated visible actuator cycles, `event_monitors` can compare an RGB-triangulated moving landmark with its stationary reference and count only thresholded down-then-return observations. The count is a noisy camera event estimate, not an actuator joint, command history, or native success. If either part is occluded or stereo fails, keep the count unchanged and report invalid evidence.
- The lower-level decision input must include the fixed high view and every moving arm's wrist view; in a camera-search stage include all three current RGB views. A planner's preferred_views are localization priorities, not a reason to hide the active camera from the multimodal decision model. This matters for garment cuff search, where a first method listed only cam_high even while wrist viewpoints were being moved.
- Future manipulation stages are validated against fields available at planning time. If an RGB-only estimate already has `now.o.ID.z`, a future stage may reference it only with a `fresh_stereo` entry gate; the gate guarantees that the same field has become a current stereo estimate before any action. Do not reference `last_stereo_z` before an actual stereo observation creates that field. If the ID itself is still absent, plan sensing first and hand off at measured evidence.
- When an accepted two-view RGB point later leaves a wrist camera, project that historical point through the CURRENT calibrated camera to estimate its expected pixel and whether it is inside the frame. This helps choose a bounded new viewpoint; the projection is not a new detection, can be wrong after object motion, and must never satisfy a fresh-stereo/contact/success gate. If the predicted pixel is inside the image but the target is absent, inspect occlusion and identity before moving toward it.
