# Focused RGB-D occlusion fix (top5_v4)

Copied controller.py, visual_evidence.py and __init__.py from top5_v3_frozen with copy_reference after reading REVIEW.md and the relevant source. The implementation changes only surface extraction, perception validity/refresh handling, and a controller guard immediately after visual update. __init__.py is unchanged. Optical flow, the restricted RGB prompt, the controller interface, and both numeric/relational Jev schemas remain intact.

The reported frame2–4 failure combines a nearly stationary scissors median with a top displaced onto robot foreground. v3 takes quantiles over the entire polygon and estimates error from a central plane residual, so this mixture can appear precise.

Surface extraction now builds an eight-neighbor graph over finite organized RGB-D samples inside each semantic/flow polygon. Edges require local metric separation below three times the median adjacent spacing, bounded to 6–15 mm. Connected components are separated before any top quantile is computed. There is no erosion, tabletop projection, absolute object-height limit, scissors rule, robot mesh, or hidden geometry. At least 12 connected samples are required; diagonal connectivity retains narrow outlines. SciPy sparse components use the existing SciPy dependency; no packages were installed.

Fresh acquisition requires a component containing at least 60% of valid polygon samples. Later measurements use an unexpired prior matched by visible category/text/label and image location. Center displacement, visible extent growth, and top-relative-to-center changes gate surface switches. Shape tolerance scales with previously visible dimensions; height-growth tolerance scales with previously visible height, with a garment deformation allowance. These are conservative heuristic gates, not object dimensions supplied externally. Ambiguous compatible components or less than 15% remaining support cause rejection. Both median and top use the selected component; top is an actual current depth sample. Bowl rims and cloth landmarks also require that component, and each landmark's central pixel must belong to it.

Uncertainty includes retained-surface residual, excluded-pixel fraction (25 mm times that fraction), and changes in relative top/extent. Diagnostics disclose component sizes, local gap, selected count, excluded fraction, prior identity/age, and rejection reasons. Uncertainty is explicitly uncalibrated. Rejections request fresh RGB and log at least 50 mm uncertainty, increased for larger rejected jumps. The controller enters its existing hold/reobserve recovery before task selection or phase processing; rejected extraction cannot count as conveyor disappearance. This conservative guard also holds for an unsupported unrelated semantic record.

Missing measurements keep their original measurement index and become observed=False, with a NOT_current_observation source and uncertainty above the existing 25 mm motion limit. Their lifetime is the unchanged configured TTL (default three controller updates, bounded to one through eight). Reusing memory does not renew its timestamp. A flow polygon without an unexpired surface prior cannot reacquire an object; fresh RGB is required. Successful component measurements always use current depth. No stale coordinates are substituted as current measurements.

Task logic is retained: public lift distance (including 100 mm) plus measured-error margin; two red button counts read from cards followed by blue confirmation; first conveyor object memory, departure, and reappearance; requested bowl count including three bowls; and clothes folding. Jev still supplies every nonzero XYZ sign. External amplitudes remain nonnegative, and the existing scaffold retains phase, arm, gripper, and rotation ownership. No privileged fields were added; runtime GPT-6 still supplies only visible semantics and 2D geometry.
