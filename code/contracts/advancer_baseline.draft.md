# Advancer baseline request draft

Status: discussion draft, not connected to a runtime. No historical observations, previous decisions or execution-result records are included. The planner assigns the controlled arm for each stage. The user confirmed that advance produces no new robot action and final-stage advance ends the plan without certifying native RoboDojo success. Gripper command behavior remains a proposal pending confirmation.

## Fixed role prompt

```text
You are the advancer in a planner–advancer robot control system.

Your goal is to advance the current stage of the planner's plan and indicate when to move to the next stage once the current stage's completion condition is satisfied by the supplied observations.

You receive the task, the current stage and its completion condition, the controlled arm, current robot state, and three current camera images.

Answer each structured question using the supplied observations and action definitions. Your motion and gripper choices apply to the controlled arm.

Return only the JSON object required by the output schema.
```

Insert the shared English action block from `tcp_action_interface.draft.md` after this role prompt. Then supply the task, stage, controlled arm, current state, step sizes and labeled current images, followed by the questions below. This is a template composition description, not implemented request wiring.

## Separate structured questions

Each row is one categorical question. Questions may share one multimodal request and one structured response; they are not eight API calls. The rotation choices are constrained jointly by the shared action definition.

| Output key | Question | Choices |
|---|---|---|
| x | Which world-X translation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| y | Which world-Y translation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| z | Which world-Z translation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| yaw | Which world-Z yaw rotation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| pitch | Which world-X pitch rotation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| roll | Which world-Y roll rotation direction should the controlled TCP take to advance the current stage? | negative, hold, positive |
| gripper | Should the controlled gripper open, close, or keep its current command to advance the current stage? | open, close, keep |
| stage_progress | Is the current stage's completion condition satisfied by the current observations, so that the plan should advance? | continue, advance |

Proposed gripper option descriptions:

```text
open: Command the gripper to open.
close: Command the gripper to close.
keep: Preserve the current commanded gripper target.
```

The current commanded gripper target is controller state, separate from measured aperture. If this keep convention is adopted, expose both as current state; no previous-step record is required. Measured opening or a close command alone does not establish that an object is held.

Confirmed stage option descriptions and execution semantics:

```text
continue: The current stage is not complete. Choose actions to advance it.
advance: The current stage's completion condition is already satisfied. Set all motion channels to hold and the gripper to keep.
```

The runtime, rather than the model, changes the current-stage pointer after validating the response. For advance, do not dispatch a new robot action. At the final stage, advance ends the plan. Whether the task actually meets RoboDojo's native success criteria is evaluated separately; model-reported completion is not benchmark success and the native result is not a model input.

## Planner-provided versus fixed content

The planner supplies stage order, each stage's goal, target description, observable completion condition and controlled_arm (left or right). The runtime supplies the current stage pointer, measured state, current gripper command, current camera images and configured step sizes. The role text, action definitions, questions, choice sets and output schema are fixed by the architecture, not regenerated by the planner. Additional perception processing is outside this initial raw-image baseline and will be discussed separately.
