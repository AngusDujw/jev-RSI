## Design

- Five tasks, four paired official layouts (0–3), four conditions: pure GPT, Jev-gated reuse, fixed mean interval, fixed maximum interval. Planned total: 80 attempts.
- Paper Jev-subsection regime: zero-shot B25; GPT-6 Astra/xhigh predicts 20 actions. Pure execution cap: five actions; reconstructed Jev gate can approve one additional five-action segment.
- This extends the Jev subsection to five tasks; it does not reproduce the main table's one-shot J12/B12 Memory-task regime. Historical task-selection scores are not comparable matched-setting baseline scores.
- GPT transport: local ChatGPT Pro through an SSH tunnel; no OpenAI Platform planner calls.
- Server project: `/home/ykj/project/jev-rsi-roboicl`. Initially eight simulator workers on four RTX 4090 GPUs, two workers per card. No saved experiment images or videos.
- Mean and maximum controls will be fitted per task from observed Jev intervals after all four attempts terminate. Unscored/policy-error attempts keep their closed intervals; their final right-censored tail is excluded. No failed attempt is silently replaced.

## Jev phase — running

The batch started at source revision `ef9808c7`, using the same five tasks, layouts, initial/reset seeds, GPT model/effort, zero-shot B25 setting, simulator, action constraints and native budgets as pure GPT. Initial dispatch is five actions and Jev may approve one further five-action suffix. Existing IK and tracking guards remain active. GPU0–3 host two simulators each. Main-trial data are written under the existing `jev/` condition directory, preserving the completed `pure/` cases.

The server's stale Python CA defaults were diagnosed without changing the shared environment. Selecting the system CA bundle exposes an upstream HTTP 451 response; its existing proxy also fails TLS. The Jev requests therefore traverse the existing SSH port 7911 and are forwarded unchanged from the workstation to the official TypeSafe endpoint, using a separate Jev key. The local bridge logs them to `jev-phase-bridge/jev-requests.jsonl`, separately from GPT requests. There is no RGB in the Jev request.

### Transport interruptions — subsequent checkpoint

Both raised a client-side 60-second read timeout. At inspection the workstation Jev audit had no upstream errors and its longest recorded request was 23.31 seconds; the end-to-end path remains under investigation. The original failed attempts are retained, and their last intervals are right-censored. Raw all-attempt costs will be separated from costs on common layouts with native scores, since early interruption must not be misrepresented as equal-quality call savings.
