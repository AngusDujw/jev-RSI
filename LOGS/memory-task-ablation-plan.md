# 四任务经验对照：预先固定的协议

范围：RoboDojo stack_bowls / fold_clothes / press_by_number / match_and_pick_from_conveyor。先完成开发调试，只有取得原生成功才进入该任务的评测。

每任务无历史经验10次＋加载历史经验10次，配对相同初始化，交替组别顺序。优先10个独立未调试布局；资产不足时不把重复布局伪称独立。开发不计入评测分母，所有正式评测失败均保留。未跑通的任务不冒充已有20次结果。

两组相同：视觉检测/分割/OCR、基本任务指令解析、动作原语、Jev模型、最大动作、原生时限、当前回合反馈。off加载空历史记录，不读旧回合/候选总结/历史参数。on加载冻结task_transfer Markdown，允许其中显式声明的恢复规则。因此测的是“历史提示＋经验规则”的整体增量，而非纯文本提示效应。基础任务适配器仍有人工结构，不能称off完全没有人类先验。

历史经验参数不能藏进off默认值。每回合保存enabled、记录内容与SHA；off输入里不能有experience_memory。评测期间不能写回active经验。每任务独立报告成功数/10、配对差异、调用成本和失败分布；无统计支持不声称显著提升。

开发先各1次检查，按失败证据迭代；如同一任务连续3次跑崩或不收敛，按AGENTS.md §10暂停该任务，其他未阻塞任务可继续。旧20次预算已结束，新请求授权本轮调试与评测，但不视为无限取消失败升级规则。

单回合仍<20分钟/1.8GiB，不改变驱动和环境。全80回合可能写入较多数据，进入评测前预估空间，默认不自动消耗超过单跑5GB或2h GPU的预算。
