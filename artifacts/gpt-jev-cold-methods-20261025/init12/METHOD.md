## Complete processing method

This is an observation-driven pick-and-place method, not a replay. The user instruction is runtime task data. A structured review identifies the movable package and receptacle and establishes whether the geometric policy is applicable: a rigid, approximately rectangular package resting flat on a measured support, and an accessible open bowl. Package corners are calibrated ray intersections with its measured top plane, not potentially contaminated depth samples at a boundary. Separate support, rim and cavity measurements establish height, fit and a bounded release height. The method uses the actual pad-center offset, opening-axis orientation and an open-finger envelope; visual bracketing remains necessary because those quantities do not establish internal finger clearance or contact.

A textured patch is initialized before approach. Registration must pass inlier, spatial-support and uncertainty checks. If registration is unknown or rejected, the executable fallback requests three independently observed, semantically identified physical landmarks, rejects ambiguous correspondence, fits a rigid registration and optionally initializes a different current patch. All accepted geometry remains tied to measured references. Retention requires independently observed object motion agreeing with actual hand motion during a small, justified test lift; neither closing nor tracking alone is sufficient. Subsequent transfers recheck attachment. A local scene review distinguishes an observed external obstruction, incomplete observation, and self-occlusion. It does not demand a nonexistent swept-volume certificate. One explicitly justified upward view change can resolve a local observation gap; otherwise the method stops with that gap.

Ordinary pose feedback uses bounded drive leases, with a second lease allowed only after measured progress. Stalls stop rather than trigger repeated contact pushing. Contact, release, retreat, settling and final object relation are assessed separately. Completion requires post-release containment evidence and measured stability after actual additional simulator steps. Checkpoints preserve source identities, metric invariants, measurement provenance and phase evidence across repairs. A repaired invocation revalidates the affected scene and distinguishes an unheld source, a candidate held object and an already released object before acting. Tracker handles are never restored from memory. Limits and uncertainty are operational bounds, not certified collision safety or official task success.

## Interface

Entry point: main(api). Globals used: np, math, geo and the documented builtins only. The runtime user instruction is stored as task data and passed to structured visual reviews; no object poses, pixels, trajectory, task file or simulator predicates are preloaded. The geometric policy is selected only after current RGB-D evidence supports it.

All API arguments are documented operations: state, camera, plane_point, review, track_init, track_update, compose, control, drive, checkpoint and recall. Measurements requested through review use named points and explicit named regions, with at most ten points and two regions in initialization. Every review has a strict fields declaration. Missing measurements and measurement_errors are checked before geometry is used. Fit coefficients use geo.plane(...)["coefficients"]. Tracker observation provenance uses frame_id and reference_frame_id. A drive receipt's before/after positions are never mistaken for full states.

References include original measured top corners, independent landmark points and physical definitions, support/top planes, package height, measured bowl geometry, camera/pixel provenance, finger-envelope calculations and uncertainty. Checkpoints named reference, progress, observation and initial_samples are episode-local historical records. Fresh observation and a structured resume review are required after restart; tracker handles are recreated rather than recalled. A returned result is JSON-compatible and contains completion_proposed plus numerical and visual evidence. Explicit failures return false without claiming that physical actions were undone.

Operational bounds: two feedback leases of at most 26 and 12 calls per pose; at most two total local upward view changes per invocation; a test lift of 0.022 to 0.035 m; five three-step control updates per open/close transition; two settling comparisons. Per-call budget checks preserve downstream control reserve, and the host's shared episode budgets remain authoritative. Stalls and nonprogress stop immediately. The method does not reopen an unverified load during transfer. Initial and fallback uncertainty floors, registration errors, aperture-envelope limitations, failed fit values and actual attachment errors are recorded in evidence.

## Jev input/output cooperation

Every physical action is dispatched by api.control, either directly or through api.drive. Each request supplies exactly x,y,z,rx,ry,rz and gripper choice questions. Axis instructions explicitly name their world axis and state.processed_features.axes.<axis>.goal_relation. Jev chooses negative for decrease, positive for increase, and hold for within_tolerance. Rotation uses the documented world rotation-vector sign and xyzw quaternion convention. The gripper question reads state.processed_features.objective.gripper and chooses exactly open, close or keep. Responses are dispatched unchanged; the method never substitutes a sign or gripper choice.

The host provides current proprioception, numerical residuals, axis relations, tolerances and bounded magnitudes. Program features add the phase, semantic action label, retention-evidence status and a provenance-labelled historical object observation. Program geometry and all numerical transforms, dimensions, margins, motion residuals and attachment comparisons are calculated in Python, not delegated to Jev. Ordinary leases use pad_center targets, 0.02 m translation limits, 0.08 rad rotation limits, three native steps, 0.0025 m position tolerance and 0.035 rad rotation tolerance. Direct transition/settling controls preserve the measured pose and use the documented default bounded limits with explicit tolerances. Reached means only controller convergence and delivered gripper choice; moved is accepted for a bounded transition only with small observed hand drift; stalled stops.

Visual interpretation comes from separate api.review calls, not from Jev as an undeclared image sensor. Review fields have explicit meanings for observed external obstacle, none observed, unknown external obstruction, partial visibility and self-occlusion. A supported local action is an evidence-based bounded trial, not certified clearance. Registration recovery asks for current semantically corresponding landmarks and an optional new patch. The numerical runtime rejects ambiguous identities or inadequate metric support. The test lift maps measured agreement between independently observed package motion and actual robot motion to permission for transfer. Final completion additionally requires measured settling, hand separation, current visual containment and the measured bowl relation after release.
